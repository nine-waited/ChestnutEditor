# 实时模式格式符号显示与光标统一设计（参考 Typora）

## 1. 背景

实时模式里，标题、加粗、斜体、删除线、高亮、数学公式的符号显示和光标操作体验差，主要表现为：

- 鼠标悬停就冒出灰色符号，干扰阅读。
- 符号上的光标、选中、删除和正文不一致，例如高亮出现双光标、点击符号时光标落点不对。
- 在加粗末尾继续输入时，加粗样式会短暂失效。
- 有选区时格式被提前收起。

## 2. 目标

1. 符号上的鼠标指针和文本光标与正文完全一致。
2. 鼠标悬停时不显示格式符号，点击后才显示。
3. 标题：点击标题行任意位置即显示 `#` 前缀。
4. 符号显示后就是普通文本。选中、光标移动、删除、复制、撤销都和正文一致，不为它新增任何专门的处理逻辑。

行内代码使用同一方案（实现时一并迁移，以便整体删除旧的假符号层）。

不在本次范围：链接、图片、表格、代码块。

## 3. 现状与根因

| 问题 | 根因 | 位置 |
|---|---|---|
| 悬停就出现符号 | 监听鼠标移动并记录悬停位置，据此生成符号控件 | `markdown-live-source-hints.ts`：`pointermove`、`hoverPos` |
| 符号上的光标和选中不一致 | 符号是插入的“假符号”控件，不能被选中（`user-select: none`），用自绘的假光标 | `createHintElement`、`.chestnut-live-source-hint__caret` |
| 符号上的按键行为特殊 | 假光标有一整套自己的方向键、退格、删除、输入处理 | `handleTokenCaretKey`、`handleTextInput`、`handleBoundaryBackspace`、`handleBoundaryDelete` |
| 高亮双光标、渲染偶发失败 | 高亮不是编辑器文档里真正的格式，而是浏览器 DOM 上的背景色 | `markdown-mark-source.ts`：`highlightSpanAt`、`clearDomHighlight`、`pendingHighlight`；`markdown-dont-extend-marks.ts` |
| 输入时加粗闪烁 | 展开范围靠手算位置跟踪，再用手写解析器判断格式，边界情况多 | `serializeRange`、`parseSourceText`、`trailingPlainOffset`、`styleClass` |
| 有选区就收起 | 选区非空时直接收起 | `markdown-mark-source.ts`：`appendTransaction` |
| 插件互相干扰 | 标题符号、行内格式符号、符号提示、不延续格式、自动加粗由多个插件分别处理，结果受执行顺序影响 | `MarkdownEditor.tsx` 插件注册 |

核心问题是格式文字存在三种状态：渲染态、源码态，以及中间的“假符号提示态”。第三种状态是体验不一致的主要来源。

## 4. 设计原则

每段格式文字只有两种状态：

- **渲染态**：文档里只有样式，看不到符号。悬停不改变任何显示。
- **源码态**：符号是文档里真实存在的普通字符，只用灰色样式显示。

满足以下约束：

- 源码态下不拦截任何按键、鼠标、输入事件，全部交给编辑器原生处理。
- 源码态与渲染态的互转，使用和源码模式相同的 Markdown 解析器和导出器，不再手写解析逻辑。
- 显示效果只用行内装饰（只改变外观，不改变文档内容），不使用插入的控件。

## 5. 交互规格

### 5.1 行内格式

适用于加粗 `**` / `__`、斜体 `*` / `_`、删除线 `~~`、高亮 `==`、行内代码 `` ` ``、行内数学 `$`。

| 操作 | 行为 |
|---|---|
| 鼠标悬停 | 无变化，鼠标指针为文本输入样式 |
| 点击格式文字 | 该段展开为源码，例如 `**加粗**`；光标落在点击位置 |
| 点击符号字符的右半边 | 光标落在该字符之后（由浏览器原生定位完成） |
| 方向键移入格式文字 | 展开（与 Typora 一致，保证纯键盘也能修改符号） |
| 展开后编辑 | 与正文完全一致 |
| 光标或选区在展开段内 | 保持展开 |
| 光标离开、选区跨出展开段 | 重新解析为样式并收起 |
| 只读或仅查看模式 | 永不展开 |

展开后修改符号，按源码模式的规则解析：

- `**a**` 删掉一个 `*` 变成 `*a*`，收起后为斜体。
- 删光符号，收起后为普通文本。
- 在 `**a**` 后继续输入，新输入的字是普通文本，加粗不闪烁。

### 5.2 标题

| 操作 | 行为 |
|---|---|
| 鼠标悬停 | 无变化 |
| 点击标题行任意位置，或光标移入标题行 | 行首出现真实的 `## ` |
| 修改 `#` 数量 | 标题级别随之变化 |
| 删光 `#` | 变为普通段落 |
| 光标离开标题行 | 前缀收起 |

标题内部的行内格式按 5.1 处理，可以与标题前缀同时展开。

### 5.3 视觉

- 符号：颜色 `var(--chestnut-text-muted)`，不加粗、不倾斜、无下划线和删除线，透明度 0.8。
- 中间文字：保持对应样式（加粗、斜体、删除线、高亮背景）。
- 不改变鼠标指针样式，不使用 `user-select: none`。

## 6. 技术方案

### 6.1 第 0 步：高亮做成真正的格式

- 在编辑器中注册 `highlight` 格式，对应 `==文字==`，导入和导出都要支持，保证源码和实时模式切换内容不变。
- 删除基于 DOM 背景色的全部逻辑：`highlightSpanAt`、`clearDomHighlight`、`pendingHighlight`、`markdown-dont-extend-marks.ts` 中的透明背景清理。
- 格式工具栏和快捷键的高亮操作改为切换该格式。

### 6.2 第 1 步：删除假符号层

从 `markdown-live-source-hints.ts` 中删除与标题、加粗、斜体、删除线、高亮、数学公式相关的全部内容：

- 悬停跟踪：`pointermove`、`pointerleave`、`hoverPos`、`targetPositions` 中的悬停分支。
- 符号控件：`Decoration.widget`、`createHintElement`、标题类型的提示。
- 假光标及按键处理：`tokenCaret`、`beginTokenEdit`、`handleTokenCaretKey`、`handleTextInput`、`handleBoundaryBackspace`、`handleBoundaryDelete`。
- 样式：`styles.css` 中的 `.chestnut-live-source-hint*`、`.chestnut-heading-prefix-hint*`、`chestnut-hint-caret` 动画。

行内代码同样迁到 6.3 的方案，因此 `markdown-live-source-hints.ts`、`markdown-live-source-hint-edit.ts`、`markdown-dont-extend-marks.ts` 及其测试整体删除。

### 6.3 第 2 步：统一的源码展开插件

在 `markdown-mark-source.ts` 基础上重写。插件只记录当前展开的一段：

```ts
type Expanded = { from: number; to: number } | null;
```

**展开**（在 `appendTransaction` 中判断）

- 条件：选区进入一段格式文字；编辑器可编辑；当前不在输入法组字中。
- 用编辑器的 Markdown 导出器把该段转成文字，替换为纯文本。
- 按点击或进入方向换算光标位置。
- 本次修改不进撤销历史（`addToHistory: false`）。

**收起**

- 条件：光标或选区完全离开展开段；或编辑器变为只读。
- 取出展开段文字，用编辑器的 Markdown 解析器解析为带样式的内容并替换回去。
- 本次修改不进撤销历史。

**展开期间的显示**

- 每次文档变化后，对展开段文字用同一解析器得到符号和内容的范围，生成行内装饰：符号灰色，内容按格式套样式。
- 不再使用 `styleClass` 这类正则猜测。

**展开期间关闭的规则**

- Milkdown 自带的格式自动转换（输入 `**文字**` 自动变加粗等）和 `openingDelimiterWrap`，在光标位于展开段内时跳过。
- 否则在 `**bold` 后输入 `*` 会在展开状态下直接转成加粗，与收起逻辑冲突。
- 普通正文中这些规则继续生效。

**删除的旧逻辑**

- `serializeRange`、`tokensOf`、`parseSourceText`、`outerWrapper`、`trailingPlainOffset`、`styleClass`。
- `mousedown` 中的 `caretInSourcePrefix` 点击定位。
- `markdown-dont-extend-marks.ts` 中的 `DONT_EXTEND`。

### 6.4 第 3 步：标题对齐

`markdown-heading-source-prefix.ts` 已采用“`#` 为真实文本”的方式，保留，调整为：

- 进入、离开、输入法组字、只读判断复用第 2 步的同一套条件。
- 确认第 1 步已删除标题符号控件，避免与真实 `#` 重复显示。

### 6.5 插件注册顺序

`MarkdownEditor.tsx` 中注册：

1. 高亮格式（`highlightPlugins`）
2. 标题前缀插件
3. `openingDelimiterWrap`（光标在展开段内时跳过）
4. 源码展开插件（插到插件列表最前，先于 Markdown 格式自动转换规则处理输入）
5. 表格工具栏等其他插件

删除 `dontExtendInlineMarksPlugin` 和 `liveSourceHintsPlugin`。

### 6.6 实现补充

- 展开和收起不整段替换，只插入或删除符号字符、再调整格式。整段替换会让撤销历史无法对齐用户在展开状态下的输入。
- 鼠标按下期间不展开、不收起，松开后再判断，避免拖选时文字位置变动。
- 加粗、斜体、删除线、高亮快捷键执行前，先把展开的源码收回成格式，再切换。

## 7. 不变式

1. **展开和收起前后导出的 Markdown 完全一致。** 否则只点击一下就会出现“未保存”、触发自动保存写盘，分屏同一文件时可能互相覆盖。
2. **展开和收起不进撤销历史**；用户在展开状态下的修改可正常撤销和重做，撤销后不出现位置错乱。
3. **输入法组字期间不展开、不收起**，组字结束后再判断。
4. **任意时刻最多一段行内格式处于展开状态**，另可加上光标所在标题行的前缀。
5. **只读和仅查看模式不修改文档。**

## 8. 测试

### 8.1 自动测试

| 用例 | 预期 |
|---|---|
| 光标进入加粗再离开 | 展开为 `**a**`，离开后恢复加粗，导出 Markdown 不变 |
| 在 `**a**` 末尾继续输入 | 新字为普通文本，加粗不闪烁 |
| 删除一个 `*` | 收起后为斜体 |
| 删光符号 | 收起后为普通文本 |
| `***x***`、`~~==x==~~` | 展开和收起都正确 |
| `$x^2$` | 展开为文本，收起为公式 |
| 展开段内选区 | 不收起 |
| 选区跨出展开段 | 收起 |
| 展开状态下修改后撤销、重做 | 内容和渲染正确 |
| 输入法组字中 | 不展开、不收起 |
| 标题点击、修改 `#` 数量、删光 `#` | 级别正确变化，删光后为段落 |

### 8.2 数据安全

涉及写盘、未保存状态、分屏同一 Markdown，修改后必须运行：

```bash
pnpm test:data-safety
```

### 8.3 手动检视

悬停、点击、键盘进出、选中、复制粘贴、撤销重做、源码与实时模式切换、保存后的未保存标记、分屏同一文件、仅查看模式、侧栏切换文件。

## 9. 实施顺序

每一步单独提交、单独验证：

1. 高亮做成真正的格式（6.1）
2. 删除假符号层（6.2）
3. 源码展开插件：加粗、斜体、删除线、高亮、行内代码（6.3）
4. 源码展开插件：数学公式
5. 标题对齐（6.4）
